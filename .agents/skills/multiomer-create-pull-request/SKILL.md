# multiomeR Create Or Update Pull Request

## Workflow

Use the standard GitHub workflow to create or update a pull request. Be sure to follow the format below.

When updating an existing pull request:

- Re-read the full set of commits and diff currently included in the PR, not just the most recent commit.
- Regenerate the PR title and body from the current branch state unless the user explicitly asks for a narrower edit.
- Preserve the same section structure below when editing the PR body.

```markdown
## New Features
< bullet points describing new features added >

## Changes & Optimizations
< bullet points describing changes and optimizations made >

## Bug Fixes
< bullet points describing bug fixes made >

## Pipeline Impact

Targets that will be invalidated the next time the pipeline runs after merging:

| Impact keyword line | Reason |
|--------|-------|
| `<impact_keyword_line>` | <brief reason, e.g. "added new column to tibble xyz"> |


The pipeline impact should be generated by collecting the mandatory impact keyword lines from the commits, as they are described in the `multiomer-impact-keyword-lines` skill. If a commit does not contain at least one "impact keyword line", check the commit content manually and determine its impact. If a target appears with both `contained_target_breaking` and `cascading_target_breaking`, use `cascading_target_breaking`. If **no** commits contain any `contained_target_breaking` or `cascading_target_breaking` keywords, write "None — no existing targets are invalidated by this PR." If it is determined that no existing targets will be invalidated by the commits in this PR, simply write "None — no existing targets are invalidated by this PR".
